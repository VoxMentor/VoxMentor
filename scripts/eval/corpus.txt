## big-o
Big-O notation describes how an algorithm's running time grows as input size grows, ignoring constants and lower-order terms. O(1) means constant time: accessing an array element by index, or reading the top of a stack. O(log n) means the work halves each step: binary search on sorted data, or descending a balanced binary tree from root to leaf. O(n) is linear: a single pass over an array or linked list. O(n log n) appears in efficient comparison sorts such as merge sort and heap sort. O(n^2) is quadratic: nested loops over all pairs, as in naive bubble sort or checking every subarray sum. When comparing two functions you drop constants, so 3n + 200 is O(n) and 5n^2 is O(n^2), but constants still matter in practice: for small n, an O(n^2) algorithm with tiny constants can beat O(n log n) with large ones. The same reasoning applies to space: auxiliary memory usage is analyzed the same way, with recursion depth counted against the stack. When an algorithm is described as linear or logarithmic, the claim is about growth rate as n approaches infinity, not a promise about milliseconds on a particular machine. Amortized analysis refines this: a dynamic array append is O(1) amortized even though individual appends that trigger a resize copy all n elements, because the total copy work across n appends stays bounded by a constant factor of n.

## arrays
An array stores elements in contiguous memory so that the element at index i sits a fixed address offset from the base: index access is O(1) arithmetic. Traversal is a single pass, O(n). Insertion or deletion in the middle costs O(n) because every later element must shift to keep contiguity; in most languages this shift is done by the runtime, so a single insert can touch O(n) elements. Appending to the end of a dynamic array is O(1) amortized: the backing store doubles when it fills, and the copied elements across a sequence of appends stay bounded, giving constant average cost per append even though any single append may copy the whole array. Arrays support random access, which is what makes binary search and index-based dynamic programming possible. Two common shapes are the fixed-size array with declared length and the resizable list that grows on demand; both give O(1) index access. Multidimensional arrays are stored either row-major, with a full row contiguous, or column-major; row-major order makes iterating rows cache-friendly. Because elements sit next to each other, arrays have excellent spatial locality: hardware prefetchers fetch nearby elements into cache, which is why array traversal usually beats pointer-chasing structures such as linked lists even when both are O(n). The trade-off is the O(n) shift cost for insertions and the fixed capacity of a truly static array.

## strings
A string is typically an immutable sequence of characters: every operation that looks like editing it, such as concatenation or replacing a substring, actually allocates a new string. Concatenating n short strings with the plus operator one at a time can cost O(n^2) total characters copied, because each merge copies both sides; builders or join operations fix this by allocating once and copying each piece exactly once, for O(total length) work. Slicing a string copies the sliced range, so repeated slicing inside a loop is quadratic. Common linear-time tasks include reversing a string, counting character frequencies with a hash map, checking for the longest common prefix by scanning position by position, and building anagrams from sorted character counts. Palindrome checks use two pointers that start at opposite ends and move inward, stopping at the first mismatch, which is O(n) time and O(1) extra space beyond the input. String equality is O(n) in the general case because every character must be compared, though languages may short-circuit on a hash mismatch. Because characters are encoded as code points, indexing by byte versus indexing by character can differ in UTF-8 text: a naive byte-index loop can split a multibyte character. Interview problems often reduce to a small set of primitives: frequency map, two-pointer scan, sliding window over unique characters, and trie-based prefix lookup.

## hash-maps
A hash map stores key-value pairs indexed by a hash of the key, giving O(1) average lookup, insert, and delete; the worst case is O(n) when every key lands in the same bucket, but good hash functions and resizing keep that rare. Hash sets are the same structure without values, used for membership tests and deduplication. The classic pattern is the frequency count: iterate once, increment a counter per key, then read the map, turning problems like two-sum into a single pass that asks whether the complement of the current value was already seen. Because lookup is constant time, a nested search that would be O(n^2) over pairs becomes O(n) with a map of values seen so far. Iteration order over a hash map is not sorted by key, and some implementations do not guarantee stable order across runs, so sort separately when output order matters. A custom key type must implement both equality and a hash consistent with it: equal objects must hash equally, or lookups silently fail. Memory overhead per entry is larger than an array slot, so maps trade space for speed. Common variants add features: an ordered map preserves insertion order, a concurrent map supports parallel access, and a counter is a map specialized for integer counts with increment helpers.

## linked-lists
A singly linked list stores data in nodes where each node holds a value and a pointer to the next node, ending with null. Unlike arrays, nodes live wherever allocation puts them, so there is no index access: finding the element at position k walks k pointers and costs O(k), and reaching the end costs O(n). Insertion and deletion at a known node are O(1), because only the neighboring pointers change: relinking a new node between two existing nodes never shifts data. The standard reversal keeps three pointers: previous starts null, current walks the list, and at each step the current node's next pointer is flipped to previous before advancing. This in-place reversal is O(n) time and O(1) space; the recursive version is O(n) space on the call stack. Finding a cycle uses Floyd's tortoise and hare algorithm: a slow pointer advancing one node and a fast pointer advancing two meet if and only if a cycle exists, using O(1) space. Merging two sorted lists splices nodes by relinking, never copying values, for O(n + m) time. Dummy head nodes remove the special case of inserting before the first element. The core trade-off against arrays: cheap local edits and no shifting, but no random access and poor cache locality because nodes are scattered.

## stacks-queues
A stack is last-in first-out: push adds to the top and pop removes from the top, both O(1) over a dynamic array or linked list. The call stack follows this model, which is why recursion unwinds in reverse order of invocation and why deep recursion can overflow the stack. A queue is first-in first-out: enqueue adds at the back and dequeue removes from the front, matching task scheduling and level-order traversal. Implementing a queue naively on an array with front removal is O(n) per dequeue because every remaining element shifts; a circular buffer with head and tail indices fixes this to O(1) amortized. Two stacks can simulate a queue by pushing onto one and popping from the other, reversing order once, with each element moved at most twice. Classic stack problems include matching brackets, where every closing delimiter must match the most recent unmatched opener, and evaluating postfix expressions by pushing operands and reducing when an operator appears. Monotonic stacks resolve the next greater element problem in one pass: elements that cannot answer the query are kept until a larger value arrives. Queues power BFS since the frontier must be explored in arrival order. Both structures expose only their ends, and that restriction is exactly what makes their invariants easy to reason about.

## two-pointers
The two-pointer technique places two indices into a sequence and moves them according to a rule until they meet or cross, usually turning a nested-loop search into a single pass. On a sorted array, the pair starting at the left end and the right end can find two numbers that sum to a target: if the sum is too small, advance the left pointer; if too large, retreat the right pointer; each step discards at least one candidate, giving O(n) after the O(n log n) sort. The same idea checks whether a string is a palindrome by comparing mirrored characters and stopping at the first mismatch. A slow-and-fast pair removes duplicates from a sorted array in place: the slow pointer marks the write position, the fast pointer scans ahead, and values are copied only when they differ from the last kept value, giving O(n) time and O(1) extra space. Two pointers also merge two sorted arrays or linked lists by always taking the smaller head value. Choosing the movement rule is the whole problem: pointers must move in a direction that provably shrinks the search space, which usually requires sorted input or a monotone condition. When input is unsorted, sorting first is often acceptable, or a hash set replaces the scan and avoids the sort.

## sliding-window
A sliding window maintains a contiguous range over an array or string with two indices, expanding the right edge to admit elements and contracting the left edge when a constraint breaks. Fixed-size windows are trivial: accumulate the first k elements, then add the incoming element and subtract the outgoing one, giving O(n) for every window sum. Variable-size windows solve problems such as the longest substring with at most k distinct characters: expand right, and while the window violates the constraint, advance left and update state until it holds again. The key property is that each index enters and leaves the window at most once, so the whole sweep is O(n) with O(1) or O(k) state, replacing the O(n^2) enumeration of all subarrays. Typical window state is a hash map of character counts, a set of unique items, a running sum, or a count of violations allowed to remain. Correctness rests on the invariant that at every moment the window satisfies the constraint, or the violated condition is being repaired as the left edge moves. Windows must be contiguous; if a problem allows skipping elements, a different technique such as two pointers over sorted data or a heap applies. Careless boundaries are the usual bug: off-by-one at the right edge when the window should include exactly k elements, or forgetting to reset state when the left edge jumps rather than steps.

## binary-search
Binary search finds a target in a sorted sequence by repeatedly halving the search range: compare against the middle element, keep the half where the target can still lie, and stop when the range is empty or the midpoint matches. Each comparison discards half the remaining elements, so the range sizes n, n/2, n/4 ... reach 1 after about log2(n) steps, giving O(log n) time and O(1) space for the iterative form. The precondition is sorted input with a consistent ordering; without it the halving argument fails. Variants search for the first position satisfying a predicate rather than an exact value: lower bound returns the first index whose element is at least x, upper bound the first strictly greater, and both work by keeping a candidate answer while shrinking. Binary search also answers optimization questions over a monotone predicate, such as the smallest capacity that lets a delivery finish within d days, by searching the answer space instead of an array. Boundary handling is where implementations break: mid must be computed as low plus half the distance to avoid overflow in some languages, the loop condition must match whether the bounds are inclusive, and the update must move the bound past mid or the loop can stall. On linked lists the midpoint lookup still works but random access is missing, so the slow-and-fast pointer pair finds the middle in O(n) instead.

## sorting
Merge sort splits the array in half, sorts each half recursively, and merges the two sorted runs by repeatedly taking the smaller front element. Because every level of recursion merges the entire array, the work per level is O(n) and the depth is O(log n), giving O(n log n) worst-case time; it is also stable, meaning equal elements keep their original relative order. The cost is O(n) auxiliary space for the merge buffers. Quick sort partitions around a pivot by moving smaller elements left and larger right, then recurses on each side; with a good pivot the partitions halve the input and the average time is O(n log n), but a consistently poor pivot such as the smallest element on already-sorted input degrades to O(n^2). Randomized or median-of-three pivot choice makes that unlikely in practice, and in-place partitioning removes merge sort's extra memory, which is why quick sort is often faster despite the worse theoretical worst case. Heapsort achieves O(n log n) worst case in place by building a max-heap and repeatedly extracting the maximum, trading cache-friendly partitioning for guaranteed bounds. Counting sort runs in O(n + k) for integers bounded by k by counting occurrences and writing them out in order, abandoning comparison-based lower bounds entirely when keys are small integers.

## bst
A binary search tree orders every node so that all values in the left subtree are smaller and all values in the right subtree are larger, recursively applied at every level. Searching, insertion, and deletion each follow one root-to-leaf path, costing O(h) where h is the height. In a balanced tree the height is O(log n), giving logarithmic operations; if inserts arrive in sorted order into an unbalanced tree, the structure degenerates into a linked list of height n and every operation degrades to O(n). Self-balancing variants such as AVL trees and red-black trees restore logarithmic height with rotations after each modification. In-order traversal of a BST visits values in ascending sorted order, which is why in-order scans and successor lookups are natural. Finding the minimum walks left from the root until a node has no left child; the maximum mirrors it on the right. Deletion has three cases: a leaf is removed directly, a node with one child is replaced by that child, and a node with two children is replaced by its in-order successor, the smallest value in the right subtree, which is then deleted from the right subtree. Range queries follow by descending to the lower bound and collecting until the upper bound is passed. BSTs add ordered traversal and predecessor-successor queries on top of hash-map-style lookup, at the cost of maintaining balance.

## tree-traversals
Depth-first traversals differ only in when they visit the node relative to its children. Preorder emits the node, then recurses left and right; it produces a copy-friendly sequence and is how expression trees serialize. Inorder emits left, node, right; on a BST this yields values in sorted order. Postorder emits left, right, node; it is the order for freeing a tree or evaluating an postfix expression, since children are handled before the parent. Each visits every node once, O(n) time, with recursion stack depth O(h). Iterative versions replace the stack explicitly: for preorder, push the right child first so the left is popped first; for inorder, push the whole left spine, then pop, visit, and move right. Level-order traversal is breadth-first: a queue starts with the root, and each iteration dequeues a node and enqueues its children, visiting top to bottom and left to right within a level; the queue never holds more than one level's nodes, so its size peaks at the widest level. Morris traversal threads temporary links to successor nodes and achieves O(1) extra space by using the tree's own null right pointers as return paths. Choosing a traversal is driven by what the problem needs: sorted output means inorder, level grouping means a queue, and processing children before parents means postorder.

## heaps
A heap is a complete binary tree stored in an array, where the parent at index i holds the element at 2i plus one on the left and 2i plus two on the right. The heap property says every parent is ordered with respect to its children: a min-heap's parent is never larger than its children, so the root is always the minimum; a max-heap mirrors this for the maximum. Completeness keeps the array dense with no gaps, which is what makes index arithmetic valid and gives O(1) access to the top element. Pushing appends at the end and sifts the new value up while it violates the order with its parent, walking at most the height, O(log n). Popping the root replaces it with the last array element and sifts it down, swapping with the smaller child in a min-heap, also O(log n). Building a heap from an unordered array bottom-up in place takes O(n), not O(n log n), because most sift-downs start near the leaves and move tiny distances. Heapsort pops the maximum n times into the array tail for O(n log n) in place without extra buffers. The priority queue abstraction wraps these operations and powers scheduling, Dijkstra's frontier, and top-k selection: peek is O(1), insert and extract are O(log n), and the structure never provides sorted order overall, only access to the extreme element.

## bfs-dfs
Breadth-first search explores a graph in layers using a queue: the start node is enqueued, and each dequeue marks the node visited, then enqueues unvisited neighbors. Nodes are visited in order of distance from the start, so the first time BFS reaches a node, the path taken is a shortest path in edge count; that is why BFS solves unweighted shortest paths and level-order problems. visited must be marked on enqueue rather than dequeue to avoid pushing the same node twice through different parents, which would blow up the queue on dense graphs. Time is O(V + E) with adjacency lists, since every vertex and edge is processed a constant number of times, and the queue holds at most the frontier. Depth-first search dives along one path using a stack, or recursion, backtracking only when a dead end is reached; it also runs in O(V + E) but its memory is the path length, O(V) worst case. DFS underlies cycle detection with three-color marking, topological sort on directed acyclic graphs, connected components, and maze backtracking where a state is undone after exploring it. Which to choose depends on the question: distance in an unweighted graph means BFS; exhaustive exploration, ordering, or cycle structure means DFS. On weighted graphs with non-negative weights neither suffices alone, and Dijkstra's algorithm with a priority queue takes over.

## dijkstra
Dijkstra's algorithm finds shortest paths from a single source in a graph whose edge weights are non-negative. It maintains a min-heap keyed by best-known distance, starting with the source at distance zero and all others at infinity, and repeatedly extracts the vertex with the smallest tentative distance. When a vertex is extracted, its distance is final: any alternative route to it would have to arrive through a vertex whose distance is already at least as large, and non-negative weights cannot shrink it afterward. Each extracted vertex relaxes its outgoing edges, and an improved distance updates or inserts that neighbor in the heap, costing O(log n). With a binary heap the total is O((V + E) log V), and each vertex may be inserted multiple times with stale entries left in the heap; those are skipped on extraction by comparing against the recorded distance. The non-negative weight requirement is essential: a negative edge can shorten a path after its target was finalized, which is the case Bellman-Ford handles by relaxing every edge V minus one times and detecting a further improvement as a negative cycle. Fibonacci heaps reduce the theoretical bound but add constant factors that rarely pay off. Applications include route planning, network latency, and as the inner loop of A star when a heuristic guides the priority queue toward the goal.

## greedy
A greedy algorithm builds a solution by always taking the locally optimal choice at each step, without reconsidering earlier decisions. It is correct only when a greedy-choice property holds: an optimal solution contains the greedy pick, so choosing it leaves a subproblem whose optimal solution completes the whole. Exchange arguments prove this by showing any optimal solution can be swapped to the greedy one without getting worse. Classic examples: activity selection sorts by finish time and always takes the next compatible meeting, maximizing count; coin systems like standard denominations allow taking the largest coin not exceeding the remainder; Huffman coding repeatedly merges the two rarest symbols to build an optimal prefix code; Kruskal's and Prim's algorithms grow a minimum spanning tree by always adding the cheapest edge that connects a new vertex or component without forming a cycle. When the property fails, greedy gives a locally good but globally poor answer: on a graph with negative edges Dijkstra's greedy finalization breaks, and fractional knapsack is greedy-optimal while its 0/1 variant needs dynamic programming. The practical test is to try to construct a counterexample; if greedy choices cannot be arranged into a failure, an exchange argument usually formalizes correctness. Greedy implementations are typically simple, single-pass or sort-then-pass, with O(n log n) dominated by the initial sort.

## dynamic-programming
Dynamic programming solves problems with overlapping subproblems by computing each subproblem once and reusing the answer. Top-down memoization wraps recursion in a cache: before recursing, check whether the result is stored; this computes only the states actually reached, and a hash map or array keyed by the subproblem parameters holds completed results. Bottom-up tabulation fills a table in an order where dependencies are solved first, usually nested loops over states, trading possibly-unneeded entries for no recursion overhead and no stack depth. Both need the optimal substructure property: an optimal solution is built from optimal solutions to smaller instances. The 0/1 knapsack recurrence considers each item once and decides take or skip, taking the better of the value gained plus the sub-answer with reduced capacity versus the sub-answer without the item, giving O(n times capacity) time. The longest common subsequence fills a two-dimensional table from the empty prefixes, each cell taking the better of dropping one character from either string. The knapsack name is also the pattern's label: identify the state, write the recurrence, choose base cases, and fix an evaluation order. Space is often reduced by keeping only the previous row when a recurrence depends on a bounded window of earlier states, and pruning unreachable states keeps tables small in practice.
